# M25 实施计划

判断：`PROBE_FIRST`。就绪：`READY`（仅首个协议试验；数据库/驱动尚未实测，全库迁移尚未就绪）。旧路线已保存在bak/mysql-otel。规格见 [M25](../../docs/MODULES/M25_POSTGRES_FACTS.md)。

1. **这次做成什么：** 首特性只验证隔离PostgreSQL和候选psycopg异步池在Python3.14.7双平台的事务/取消/唯一键/CAS/行锁，并交付完整持久消费者与类型映射盘点。后续范围为全业务事实迁移和隔离恢复；探针成功后原位补具体迁移计划，不预写未证实SQL。
2. **从哪里改：** 原AGENTS分支规则及M08/M10/M15/M18/M20/M22/M23 handoff；现有仓储、合成权益、migrations、装配/维护/评测工具；根锁与infra/deployment。先读LOCAL_SETUP/.local/DEPENDENCIES，只看所需连接字段类别，凭据不入报告。`feature/m25-postgres-protocol`从同步main建立，核对bak/mysql-otel旧快照不变；数据库自托管，不购买RDS。
3. **怎样证明：** 隔离实库固定动作验证回滚、冲突、短事务并发、取消/关闭和所需隔离语义；MySQL只读盘点，应用既有源库不写。离线验证类型/金额/前导零/hash边界；首特性模型0次。后续迁移须完整表/关系/状态校验及真实备份恢复、历史回读与幂等，不以连通性替代。
4. **什么时候停：** 驱动/SDK不支持3.14.7、授权连接不可用、事务语义不成立或数据/签名差异无法解释时保留诊断并停止。不得切现网、删MySQL或用未验saver批准执行。试验参数/超时按本轮动作写入口，不把历史金额变成规则。
5. **怎样交付：** 仅按首特性实证写M25 handoff/STATE，合入main并同步；不能标全库已迁。下一特性为全持久适配/导入/隔离恢复，由用户另启，依试验结果更新这一份PLAN。
