# M39 实施计划

规格：[最终清理不必要的文件](../../docs/MODULES/M39_FINAL_FILE_CLEANUP.md)。
实施基线：干净同步`main` / `ce2aa41`；用户2026-10-05明确授权完成全部M39。
判断：`VERIFY_EXISTING → DIRECT`。[M37](../../handoffs/M37.md)/[M38](../../handoffs/M38.md)前置已完成，第一项在`feature/m39-tracked-file-cleanup`实施；验收/Git交付后继续第二项，不启动其他M。

## 1. 做成什么

只删除有证据确认不必要的文件和空目录，修正直接引用，留下必要结果。不给本M附加文档重写、课程/页面建设、架构调整、部署发布、数据重置或自动清理系统。

## 2. 从哪里改

先读AGENTS、STATE、ROADMAP、当前规格及届时的M37/M38实际handoff；历史清理参考[M32](../../handoffs/M32.md)、[M18](../../handoffs/M18.md#全项目清理与任务收尾)。核对当前进程、运行/发布/恢复/审批引用；真实依赖只读检查前读取LOCAL_SETUP和受保护依赖索引。

| 顺序/拟实施分支 | 候选范围 | 允许动作 |
|---|---|---|
| 1 / `feature/m39-tracked-file-cleanup` | 已完成PLAN、重复过程文档、无消费者源码/CLI/模板、冗余测试与资源 | 逐项证明后删除，修正直接链接/打包/导入引用；保留独立测试断言 |
| 2 / `feature/m39-local-file-cleanup` | `.local/tmp/`等过程产物、已解决诊断副本、重复导出/构建/传输和空目录；有证据的云端过程副本 | 精确单文件删除再删空目录；保留凭据、来源、当前配置、有效状态和受引用资产 |

第一项已确认并删除M18的完成PLAN：其5项步骤及结果均已由M18交接覆盖，唯一直接消费者是本PLAN中的候选说明，已同步修正。受控672文件无大于100字节的完全相同文本文件，606个测试函数无归一化同AST重复；包配置及稳定CLI仍有用途，不凭短文件或名称删除。实际验收与删除结果见[交接](../../handoffs/M39.md)。

第二项继续核对现存`.local/tmp`的M28/M29构建、浏览器与导入过程副本、test-suite-pruning恢复资料，以及M37暂留系统临时环境；目录名不是删除依据。保留未解决断连诊断、受发布绑定报告、来源/凭据/配置、预算与恢复闭包；云副本无充分消费者证据则暂留。不输出凭据正文，不全盘扫描或清空云根目录。

## 3. 怎样证明

每个目标确认绝对路径/祖先重解析点、用途、消费者、保护关系和必要替代；测试删除逐条映射保留断言。执行前后记录实际存在性和数量/字节变化，不预估冒充释放空间。受保护对象只按必要范围核对，不生成永久全盘清单。

按影响检查Markdown路径/引用、CLI/动态装配、包资源/构建、pytest收集与相关回归；过程副本删除不触发全量测试或模型调用。候选命令包括`git diff --check`及`py -3.14 -m uv run --locked pytest --collect-only -q`，只有删除影响测试时运行后者。发布/运行引用必要时只读查询，不写数据库或调用模型。

## 4. 什么时候停

确认对象已实际处理、剩余对象有具体暂留原因、适用检查通过后，两个特性结束。工具拒绝按AGENTS处理并继续其他对象；不绕过拒绝，不把未删除报为已删除。不得因最终版要求清空保留安装、active/previous、预算、审批/UNKNOWN或唯一恢复证据。

## 5. 怎样交付

逐特性按AGENTS验收/中文提交/推送/合并/六SHA同步，main不复验。忽略文件不会进入Git，实际结果写必要`handoffs/M39.md`与STATE；不提交临时清单、诊断副本或秘密。受控删除由Git恢复；忽略对象只有确认无唯一价值或有有效替代才删除。收尾删除本轮中间产物及完成PLAN并修正链接，停止于文件清理，不启动新M。
