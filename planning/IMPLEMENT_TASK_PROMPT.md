# 实施入口 v2：一个主写者，按已授权范围顺序完成

执行我指定的当前 M / IMPLEMENT.md / Sxx 文件。先读 AGENTS、CONTRACTS、PROJECT_STATE、当前任务与直接前置交接，再读相关实现/测试；检查实际分支、HEAD、工作区及规划基线之后的相关差异。原图只在任务需要或有来源疑问时按页核对，不默认重读全部材料。

已有实施任务就直接进入必要检查、实现与测试，不再拆下一轮子 Prompt。没有充分任务规格时只补本次真正缺失的决定，不重规划整个项目。旧任务的路径/字段与上一 S 合法实现不同时，先核对版本和契约，做最小兼容调整；不能退回旧 commit 重建。

默认同一个 M 使用同一个主实施会话。用户只授权当前 S 时完成后停下；明确授权整个 M 时按已确定依赖顺序逐项完成，每项先实现、测试、检查差异并记录，再进入下一项。不要让多个 Agent 同时修改该工作区、锁、迁移或共享测试数据。只读复核可以针对固定 commit；发现问题由主写者修复。

只修改任务允许路径及获准的共享文件；不得覆盖用户改动、reset/clean、重建infra或伪造完成。先复现失败/建立关键断言，再实现最小修改；类型/静态检查、相关单元及回归测试必须给真实命令和结果。live、云变更、破坏性测试按明确目标与授权，不因文件说“必测”就默认获准。

发现契约冲突、关键前置不成立、需要新增服务/费用或修改未授权范围时停在最小阻塞点；离线可继续部分可完成，但未获运行证据的能力保持PENDING/NOT_RUN。不删除难例、关闭失败测试、伪造返回或用另一模型赞同替代验证。

完成后输出实际修改/原因、命令与退出码、未执行项、版本和资源变化、只针对本任务变更的回滚办法。小S的状态集中更新 handoffs/Mxx.md 的任务表；不强制生成三份同义报告。代码实现commit与后续报告commit分清，未知SHA不编造。

用户已授权commit/push时，显式暂存本任务路径，检查暂存差异和敏感材料后提交、普通push并验证远端HEAD；否则只报告未提交差异。不做空提交，不force。每个S可有独立可验证commit但不必每次另起会话。模块结束再做一次对固定commit的独立只读审查，有问题回原主会话修复、重测。
