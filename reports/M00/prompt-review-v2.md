# 22模块与规划模板复核 v2

输入commit：4724a386ceecf62efe318569526103e3233d5db6。逐份读取planning/modules的M00–M21全文，保留原模块ID、阶段、直接依赖、核心机制与失败案例；本轮修改的是规范与辅助工具，不实施业务模块。

## 统一修订

固定拆分改为DIRECT/DECOMPOSE/PROBE_FIRST/VERIFY_EXISTING，分别交付完整实施任务、必要S、探针或既有成果复核。一个M默认同一主会话顺序实施；测试与实现一起交付，handoff按模块集中记录。原PDF已在本地，但不在公开GitHub；网页规划会话仍需附件或授权本地访问。

## 每模块实质复核

| 模块 | 问题或需明确的边界 | 修订 |
|---|---|---|
| M00 | 已有成果不应重新生成，也不能只看最后一步就通过 | 当前已有 M00 设计和文档工具，优先判断 VERIFY_EXISTING。S06 必须列出 S01–S05 的要求—既有产物—本轮检查—缺口；缺失项调用对应任务补齐，不要求重新开五个会话。S01 核来源与差异，S05 检文档/上下文/原件工具；两者都不是 Agent 业务实现。兼容性以可复查的两种接口视角和三个走查为依据，不把会话数量当质量指标。 |
| M01 | M01占位类型与M02正式契约有重建风险 | 只创建符合 M00 语义的最小类型子集和 fake 适配；标注占位接口 NOT_IMPLEMENTED。M02 在这些定义上补全，不另起第二套 Request/Response。异步实验优先事件/任务完成状态等确定性断言；耗时对照给宽容阈值与环境，不以毫秒级时序作脆弱 CI 门禁。新增依赖与根锁由本模块主写者统一更新，uv 不在 PATH 时用已安装的 `py -3.11 -m uv`，不重装工程。 |
| M02 | 类型/测试规格与真实存储实现需分期 | 本模块发布唯一类型、注册表与合成 fixture；复用并补全 M01 最小类型。数据库唯一约束/权限语义先形成规格，M08 实现最小消息/问题账本，M10 扩展生命周期和投影，M15 完成审批/操作恢复；不要提前实现后三个模块。订单等编号用字符串，金额用 Decimal 或规范十进制字符串并明确币种/精度。只有实际执行过的测试才算通过，不能把契约样例标成 MySQL 行为验证。 |
| M03 | 模型工具调用探针不应隐式依赖尚未完成的MCP模块 | 本模块的 tool calling 能力探针使用静态工具 schema 与受控结果，验证模型协议而非 M06 的 MCP。真实 MCP 往返由 M06 负责，端到端调用由 M07/M08 负责，避免形成隐藏依赖环。网关计数包含底层 SDK 实际尝试，关闭/纳管 SDK 默认重试；缺少授权额度时离线实现可完成，live 单列 PENDING_LIVE。 |
| M04 | 规则前置与600唯一主意图决策需要一致 | 清洗/抽取可以生成 RuleMatch 候选与话语功能标签，但不在300阶段确定最终主意图并路由 SOP；规则决策在600统一消费。新结果必须带来源；明确更正与普通冲突区分，低可信结果不能覆盖已确认实体。先用现有 Regex/API 方案，不为补齐层数再接一个未经验证的小模型。 |
| M05 | 召回语料隔离及导入状态不能依赖未来M10 | 只把获准的 train/reference 语料写入检索集合，dev/test 问题及其近义变体组不得入库；保持查询集与索引语料的 manifest 可比对。M05 的导入批次状态可用有界原子文件 manifest，或复用已存在的受控存储，不能依赖尚未实现的 M10。旧 p00_acceptance 是协议探针而非意图库，禁止重建它来冒充业务验证。重启持久性测试需明确维护/隔离目标授权。 |
| M06 | stdio真实协议不等于自动具备租户鉴权 | stdio 本身不证明用户身份。可信 ToolGateway 必须从已验证请求注入工具执行上下文，通过不暴露给模型的受控会话/内部信封传递，并在 Mock 服务端再检查对象归属；正文参数不得覆盖身份。所称500/限流是模拟下游故障，不混同 stdio HTTP 状态。真实 list_tools/call_tool 可不调用真实模型，本模块不依赖 M03。调用ledger用于合成协议断言；持久副作用账本由 M15 实现。 |
| M07 | SOP执行结果和业务Question状态不能混用 | SOPResult 返回缺槽位/下一步，由主流程映射到 Question.WAITING_SLOT 和 Response.CLARIFY；执行器不自行写问题状态或重做主意图识别。沿用已发布 ToolResult/预算，不另造调用网关。M07 的最小 SOP schema 由 M14 增量扩展，配置数不是拆任务依据；三个相似 SOP 可以一个任务连同测试完成。 |
| M08 | 最小闭环必须拥有持久化责任且不暗称完整多轮 | 实现最小 MySQL messages/runs/questions 接收记录、同消息幂等及终结状态落账，迁移脚本限定本项目业务表，不改旧P00探针。M10 在此基础增量扩展；内存Repository只用于离线测试，不能通过正式持久化验收。此阶段只承诺本条完整输入的处理，缺槽位返回 WAITING_SLOT 并提示补齐完整问题；未做归属/合并就不承诺跨消息自动补槽。M09/M12继续扩展同一主流程和意图服务，不新造平行实现。 |
| M09 | 融合评测和后续接入不应再造检索接口 | 先复用 M05 检索Port/返回字段，能力确有差异再增量扩展；不要因文件名为Hybrid就复制一套不兼容接口。对照使用相同查询集、候选预算和版本，记录各路线原始分数及融合来源；已看 test 错例再调参后不能仍称该集合完全未见，冻结发布前另保留未参与选择的样本组。 |
| M10 | ACTIVE-only会漏补槽，缓存故障测试可能影响共享环境 | “开放问题”明确包含 ACTIVE、WAITING_SLOT；WAITING_APPROVAL 只作受授权的上下文候选，普通新消息不能批准/恢复挂起run。原图 ACTIVE 过滤在本项目扩展状态机中不是直接照搬的枚举条件。基于 M08 账本增量迁移，审批执行逻辑仍留 M15。缓存丢失通过隔离测试实例或本测试专用前缀模拟，禁止对共享 Redis 执行 FLUSHALL/FLUSHDB。 |
| M11 | 等待状态、实体更正和数据库失败降级有歧义 | 复用 M10 开放问题集合，不能把 WAITING_SLOT 从补充归属候选中排除。WAITING_APPROVAL 只提供上下文/更正入口，绝不隐式resume；更正计划必须使旧批准失效。明确A改B是实体更正事件而非证明A=B的union边，同订单不同诉求也不能只因编号一致合并。MySQL不可用时普通有状态请求失败关闭；仅显式标注的无持久化只读预览允许仅当前消息，不伪报已保存/已处理。 |
| M12 | 增强既有主链而非重建；区分策略重放和模型随机性 | 在 M08 同一图/服务上替换已标注的 passthrough、增强检索和上下文节点，回归原MVP行为，不并存两套流水线。统一使用 Response.outcome=REJECTED；IntentDecision.decision=reject 是另一层枚举。离线固定fixture/相同版本要求策略重放一致，真实随机模型不承诺逐字/候选顺序完全一致；安全与业务状态不变量必须始终成立。 |
| M13 | 训练环境可行性、不可复现参数与效果验收需要分开 | 先验证当前 Windows/Python 的 FastText binding；不支持时以已授权 Linux/WSL 小探针为先，不偷偷改主workspace环境。只设置实际绑定支持的随机种子/参数，记录线程数与模型hash，不虚构多线程训练逐字节可复现。训练—推理共用预处理，数据不足只能验流程，不能称泛化质量通过；默认关闭的模型也应保留可验证的独立训练/推理结果。 |
| M14 | 配置治理不应提前完成或假装M15持久审批 | 在 M07 的 SOP schema/执行器上增量治理，15+是有差异的情境而非必须15份重复SOP。审批后变更场景在本模块验证 NEEDS_APPROVAL/拒绝写入与计划绑定，真实批准恢复及副作用由 M15 接通后补验；配置发布不改变已开始run的固定快照。静态校验有限表达式语法，不承诺能判定任意程序终止。 |
| M15 | 持久性必须包含下游效果账本与并发执行边界 | 优先 PROBE_FIRST 检验实际 saver/锁定依赖；通过后再定实现任务。领取执行权、审批校验、expected_version 和 IN_FLIGHT 标记要在同一受控事务中裁决；普通消息更正不能与旧计划执行无约束并发。操作已进入外部执行后不能谎称撤销了已发生效果，需查询/对账或受授权补偿。合成下游的幂等效果记录也必须跨其重启持久；内存计数无法证明崩溃恢复。测试区分网络调用次数与业务效果次数，UNKNOWN不得盲目重试。 |
| M16 | 自然语言润色的事实保证不能只靠另一轮模型判断 | 权威金额、编号、执行状态和证据引用由结构化字段/模板输出，润色只改非事实措辞；不能可靠验证的自由文本整段回退模板。第二个LLM说“无幻觉”不是确定性保证。调试视图复用已有trace，缺失或丢弃的非关键trace显式标注；关键业务/操作审计不能随日志轮转一起丢失。CLI/API已满足检验时无需额外三套前端。 |
| M17 | 500条规模目标不能掩盖样本独立性与评测泄漏 | 保留500+目标，但分别报告独立case/变体组/样本数与实际核验覆盖；没有足量可核验数据时诚实未达标，不复制改写凑数。已用于排错的smoke/regression集与未见发布heldout分开，任何依据test结果调参都记录污染并另留未见组。验收按所测子集和配置报告，不能把0个已发现越权外推成绝对无风险。 |
| M18 | 版本回滚与挂起run快照的兼容缺口 | outbox只解决幂等任务投递，不等于跨模型/向量/文件的原子发布。先准备不可变ReleaseManifest及所有工件，校验后以单一事实源中的版本化active指针切换；run固定完整manifest。回滚不强改已审批run的SOP/参数绑定，变更须重规划/重新审批。旧工件仍被待审批或待对账run引用时不得按“两版本上限”直接删除，容量不足先停止发布。 |
| M19 | 运维测试必须明确目标和授权，不能由模板触发破坏 | 先列实际服务/挂载/端口/数据目录与本次测试目标，只读盘点不等于允许重启/删除/恢复。破坏性演练和恢复使用明确隔离目标，写出中止与清理范围；不触碰共享p00探针或其它项目。固定数字是设计参考而非实测容量保证，报告真实期限/负载与剩余风险。无当前云授权时可以完成部署计划和离线校验，运行验收保持待执行。 |
| M20 | 迁移应验证复用及事实时间语义，而非复制引擎 | 复用已验收引擎，仅新增合成物流适配/配置与必要契约增量；每次变更回归客诉场景。延迟/签收判断明确事件发生时间、接收时间、时区和数据更新时间，缺失/乱序轨迹不能直接断言丢件或自动补偿。展示/简历只引用可复查report，演示脚本不等于生产上线或千万级性能。 |
| M21 | 可选框架对照应先验证边界和依赖而不是重写主链 | 主路线保持不变。先做接口/依赖兼容探针，必要时单独本机环境且明确与主workspace的接口，不把冲突依赖塞进根锁；只有已验证隔离方式才用profile/extra。先完成只读等价对照，审批不等价就保持只读。对照固定任务、工具、预算和版本；允许因无实际收益而结束可选支线，不强行迁移。 |

## S06的真实含义

S01核来源，S02定语义，S03定边界，S04走查，S05验工具，S06合并检查证据。已有产物无需重生成，缺口也不能跳过；新S06要求覆盖表并允许同一主会话按相应任务范围补齐。此次没有替用户宣布S06最终验收完成，M00保持DESIGN_READY/REVIEW_PENDING。

原AGENTS和S01–S05文件保留，现有安全和路径约束继续有效；本轮未成功应用涉及这些入口的批量调整。新的具体实施组织以当前模块、通用模板、S06与WORKFLOW为准，未授权的并行写入不在默认流程。旧文件中的“可并行”是可能性，不是要求创建多个写者。

## 后续使用与限制

本轮是可用的v2基线，不承诺SDK、依赖、接口和新测试证据永远不变。后续仅修订受到实际变化影响的范围，不循环重写整套22模块。

文档/脚本实际测试见validation-v2.json；Windows原件逐字节检查见windows-sync-v2.json。没有真实模型调用、当前云端验收、业务代码测试或多模型对照实验。模型/模式建议是结合官方能力资料与本项目耦合结构的工程判断，不是本轮benchmark结果。
