# M36｜让一次真实运行成为能读懂、能追问的学习过程

**来源：** 用户2026-10-05要求；现有原始表格/JSON和Langfuse链接不足以解释后端机制。
**前置：** [M35组件工作台](M35_FRONTEND_FOUNDATION.md)、[M33课程](M33_JAVA_LEARNING_COURSE.md)实际交付；复用[M28原生观测](../../handoffs/M28.md)、[M29报告/Prompt](../../handoffs/M29.md)、[M31四路检索](../../handoffs/M31.md)。
**实施：** 三个顺序特性已交付，实际场景、完整发布与恢复证据见[交接](../../handoffs/M36.md)。目标是语义清楚的教学产品，安装了Langfuse不构成此M验收。

## 一个run的阅读方式

默认先回答“用户想问什么→系统掌握哪些资料→这次走了哪条路→在哪里等待/失败→最后能确定什么”，再展开协议/模型/持久化细节。只展示原账本、决策、证据和实际观测的投影；新增解释由确定性模板生成，不为浏览说明调用模型、不展示隐藏推理、不编造模型为什么这样想。

| 层次 | 读者看到什么 | 必须有的来源 |
|---|---|---|
| 业务摘要 | 原诉求、所属问题/补充、更正、缺槽位、结论与下一步 | PG原消息/question/receipt和原实体来源 |
| 流程地图 | 13段中实际经过/跳过的步骤、规则/检索/模型接管路径和状态 | 原stages/cascade_steps/decision，未记录则标未知 |
| 时序与等待 | 应用/两个MCP/模型/PG/图任务在何处重叠、排队、结束和恢复 | 实际span父子/时间、可追溯关联；没有排队观测就不推算 |
| 事实证据 | 模型建议、工具返回、代码验证、最终事实的区别 | 原tool_call/事实/evidence不可变引用与schema结果 |
| 模型与用量 | 每次attempt的模型、受控输入/输出、schema/tool解析、usage | 原生generation/本地诊断；actual/unknown/预留/估算分开 |
| 持久状态 | PG账本/outbox、Redis/Milvus投影、官方checkpoint和发布引用 | 受身份/版本约束的实际读取，区别本次快照与当前状态 |
| 教程与源码 | 当前步骤学什么、该读哪个函数、最小实验和常见误区 | 同M33章节和M32当前路径，不复制第二份解释 |

普通用户无需先登录Langfuse管理界面才能理解运行。工作台先提供上述投影，Langfuse/Grafana链接作为进一步诊断入口；不得把全局平台数据/密钥暴露到前端。

## 三个顺序特性

1. **运行语义投影：** 增量提供同run的摘要/步骤/实体与意图/事实来源，时间线能看正常、缺槽位、拒识、重放、取消/失败。后端投影适配器只读，先按原主体/session/run授权；拟新增类型/路由在实施时补CONTRACTS，不提前当已存在接口。
2. **机制实验和观测诊断：** 深化检索四路、事件归属/记忆、MCP双端、审批图/暂停恢复及Langfuse/指标的解释；显示真实分支/来源、同候选条件和不完整证据，教程与当前数据联动。
3. **完整学习场景与正式交付：** 串起M33课程/页面/源码；完成固定正常/失败场景的实际浏览器走查、当前版本完整发布、旧安装回退入口与本轮临时产物清理。

## 必须解释清楚的机制

**识别/检索：** 当前实体在哪段原文、是否否定/更正、采用哪次消息；文档候选与最后意图分开，Dense/BM25/fusion/rerank分数分栏并解释量纲，召回缺失和排序退化区分。Rerank关闭、未运行、失败、成功都按实显示；比较必须共享原向量和候选，不能混成质量收益。当前物流拒识等反例展示“有相似样例仍范围外”。

**记忆/持久化：** 标明当前消息归属与为什么需要用户澄清（基于已记录reason/候选），确认字段的来源/版本、outbox已写/待投影、Redis缓存缺失/过期。PG账本是业务事实，官方checkpoint是执行状态，Langfuse是诊断；不以平台缺span判断业务未执行。展示原receipt事实与当前维护记录的差别，重投本次调用数与历史原调用数分开。

**异步/工作流：** 一次请求图只画实际节点；整条13段不冒称由LangGraph运行。审批等待与执行耗时分开，pause和resume是新的运行/诊断关联，checkpoint的thread/parent/pending writes有普通话说明。取消请求、资源清理完成、业务终态/副作用未知是不同状态；未知不能显示“已失败且无效果”，不能在读取页面时隐式resume。

**观测/数字：** 同一个attempt实际usage只计一次，父级汇总不再相加；reasoning若包含在output不重复累计，缺失项标未知。请求总耗时与子span墙钟时间/CPU时间有区别，重叠span不直接求和。说明服务PID/版本/profile、原run及本次读/重投的trace。平台超时、缺页、截断、旧Tempo退役都保留明确状态和已确认事实，不重发业务“补观测”。

## 教学场景及验收

| 场景 | 页面应能说清的结果 |
|---|---|
| 优惠未到账正常查询 | 哪一条诉求、哪类意图、哪次工具、哪些金额/原证据支持回答 |
| 缺订单号→补充→更正 | 为什么先不查工具，补充属于哪个question，旧值为何失效 |
| 交错问券和订单活动 | 哪条补充关联哪件事，不能串单，歧义时怎样等待澄清 |
| 无关物流/只有编号 | 有召回候选为何仍拒识，没调用业务工具不能假装查过 |
| 同消息重投/新消息 | 原run/receipt保持、此次0调用；新消息读取当前事实的差异 |
| MCP失败/任务取消/UNKNOWN | 已发与未发边界、哪一侧失败、可确认内容、允许的下一动作 |
| 审批pause→显式resume | 原计划/版本/唯一效果、官方checkpoint、新运行与前序关系 |
| Langfuse不可用或数据不全 | 诊断缺失与业务已提交分别呈现，浏览不重放模型/工具 |

先离线核对投影/来源/计算/反例和UI状态，然后用实际原run或固定新动作验证语义；不能拿固定截图/录制成功动画当本次运行。至少沿实际业务链看一次完整结果，平台读回的模型/usage与应用计数一致；故障/审批协议用固定动作，不让每个故障重新跑模型。已有适用真实内容可复用，但新安装字节必须新的精确完整发布。

验收是按上述问题逐项得到来源可点击、术语可理解的回答；不是页面数量、span数量或截图好看。教程/页面/源码三处对应，未观察到的信息明确未知；权限、隐私、取消、预算及不可变事实不因可读性弱化。全部特性交付后停止，不自动扩成企业客服平台或启动新M。
