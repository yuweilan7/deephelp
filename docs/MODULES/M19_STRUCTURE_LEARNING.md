## 目标与结构

一个仓库、一套领域类型与会话引擎；按职责分包，不复制为学习版和正式版。当前learning/probes/evaluation已分目录，但仍随应用wheel打包，根业务源码仍大量平铺。本特性完成实际分层和可安装边界，而不是再次清理日志或创建空目录。

目标结构如下；目录有实际消费者才创建，允许按已核对的职责微调：

```text
modules/
  deephelp-app/
    src/deephelp_app/
      domain/                 # 同一套类型、规则、必要Port
      application/            # 会话、级联、SOP、记忆、审批、发布用例
      adapters/               # 模型、MySQL、Redis、Milvus、MCP、观测
      api/                    # HTTP路由、身份入口
      bootstrap/              # 配置、装配、生命周期、正式CLI
      resources/              # 运行策略、SOP/模板、增量迁移
    tests/                    # 按责任找用例，保留现有安全断言
  deephelp-tools/
    src/deephelp_tools/
      learning/               # fake、重放、故障学习实验
      probes/                 # 显式真实依赖验收
      evaluation/             # 冻结评测、训练、审核与发布准备工具
    tests/
  deephelp-services/
    src/deephelp_services/
      business/               # M20真实业务MCP与维护API的独立启动入口
      retrieval/              # M20检索MCP独立启动入口
    tests/
frontend/                     # M22创建；页面不复制后端机制
datasets/                     # 冻结训练/评测数据与版本说明
demo/                         # 演示后端、显式初始化样例
infra/                        # 保留现有中间件；M23增加应用部署
docs/                         # 当前事实、运行/学习导航、设计
planning/                     # 每M唯一短PLAN
handoffs/                     # 实施后必要证据
```

根uv workspace只增量纳入实际有消费者的包，保留Python3.14.7与唯一uv.lock；工具/服务包依赖业务包的共享领域和能力，业务包不得反向导入工具、服务启动器、demo或冻结数据。主引擎只保留一个。服务包是两个可独立启动的进程入口，不拆成多个仓库、不复制检索实现，不在M19提前创建空服务；M20实施时再创建。

demo适配器通过工具协议或显式配置使用业务类型；demo可以作为工具包内独立适配模块，根demo保留样例及说明，不再复制一份实现。显式demo模式需要相应可选组件；数据库适配尚未完成时诚实说明，M19不提前建设M20。业务装配和发布CLI中的运行/准备职责按实际消费者拆分，不按文件名判断。

不再同时创建根tools、labs、evals、scripts等重复Python入口。命令统一在相应包中，运维入口继续在infra。源码导览复用docs/learning：机制→调用入口→核心函数→最小离线样本→观察点→真实运行按钮边界，先覆盖13段主链、检索、审批与飞轮，不逐行复制源码。

## 验证与运行边界

业务数据源与模型调用方式分别配置：离线练习使用fake/冻结样本；显式演示使用demo事实；个人运行使用MySQL业务记录和真实模型。不得用“在服务器上”作为自动联网条件，不得把数据库不可用悄悄回退为JSON。

普通pytest与CI继续离线；收集前网络守卫、loopback协议测试、子进程入口与资源边界分别核对。不承诺现有socket守卫自动覆盖任意子进程、代理或将来新增的传输。默认命令/帮助/预览/测试不得触发真实模型；live使用显式入口与共享运行预算。

先核对静态/动态导入、CLI、pytest、资源、包构建和发布指纹引用，再一次迁移本特性内的职责。不盲目批量移动或删测试。相关离线回归后，因共享装配/导入变化可做一次完整离线回归；只读取摘要及失败上下文，不将全部测试源码和通过输出注入会话。

纯路径/装配等价迁移按ROADMAP做离线验证，不为“完整”串跑历史live。运行字节变化使完整发布清单失效时保留原清单/报告；新清单仍须按现有精确内容门禁生成。若本特性包含可运行新完整发布的交付，必须单列这一真实范围，不放宽指纹守卫或把旧PASS套到新包。

## 退出条件

运行包可独立安装，运行装配不读取学习工具或dev/test；当前合成业务闭环仍需显式配置独立demo MCP组件，不冒称已有MySQL业务后端。显式demo与离线工具仍可使用。领域、用例、适配、HTTP和装配职责可沿导览定位；必要命令/资源与测试消费者有效。权限、事实、幂等、审批/UNKNOWN和发布引用保持。迁移、资源或内容门禁失败即停，完成本特性后停止，不自动执行M20。
