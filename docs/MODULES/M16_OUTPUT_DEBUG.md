# M16｜事实约束回复、全链路追踪与三类调试视图

**阶段：** D 执行与治理

**前置：** M09, M11, M12；审批/恢复视图另依赖选做的 M15。

**来源：** 原 PDF 文件页 7–12、55–61、69–71。以下未由原文给出的实现细节均为本复刻方案的工程要求。

## 本模块目标
还原原文“意图调试、多轮调试、流程结果调试”三种白盒能力，让错误能定位到候选/状态/工具，而不是靠翻一段大模型回复猜问题。视觉做朴素，信息必须完整。

## 输出层
由SOPResult/已确认实体/工具Evidence生成结构化事实集，再选择确定性模板或受限LLM润色。REPLY_POLISH不能新增金额、订单号、已执行动作、成功状态或不存在的证据；语气更自然不等于业务结论可以改变。模型失败/输出不合规时直接返回模板事实，不影响账本正确性。

最终response包含code、reply、question/run/trace、状态、下一步及可见证据摘要；缺槽位与审批等待分别展示，不把“申请已创建”写成“退款已到账”。内部堆栈/秘密/跨用户数据不得暴露。

## 三类调试能力
意图视图：原/清洗文本、各层规则命中/排除、Dense/BM25/fusion候选与来源分数、最终决策和版本。
多轮视图：消息时序、question状态、候选事件、被排除的历史、补充消息归属、实体更正、记忆读写和投影版本。
流程视图：实际SOP快照、每步开始/结束/错误、工具参数与证据、预算消耗、审批及恢复点、最终事实与回复差异。

这些可通过三个CLI/API加一页简单HTML实现，不开发复杂管理平台。不把Chain-of-Thought作为可观测性目标；记录的是显式决策结果和可核对证据。单次调用串联trace_id，跨恢复可关联run/operation而不强行共用一个永不结束的trace。

## 存储和安全
从M01已有结构化事件扩展，不引入Langfuse/ClickHouse/Grafana整套。详细trace按大小/期限轮转，错误样本采样也有上限；聚合指标和业务账本的保留周期分开。debug默认本机或鉴权访问；脱敏规则兼顾可调试的稳定替代ID，导出文件避免CSV公式注入。

## 验收
任取一个错意图、错事件归属、工具超时案例；选做M15后再加入重复resume，能仅凭trace定位阶段及输入版本；三个视图复用同一底层事件而非各存一份不一致记录。回复中的关键事实必须匹配工具证据；故意让polish模型造数字时测试能阻止或回退。日志满额可轮转，不能堵塞主流程或写满root。

先交付只读核心的回复模板/校验、复用trace的三类调试入口、脱敏导出和失败例子；审批/恢复信息在M15之后增量接入，不阻塞核心调试验收。无需美化、不接内部京ME。

## 接口与分期边界

权威金额、编号、执行状态和证据引用由结构化字段/模板输出，润色只改非事实措辞；不能可靠验证的自由文本整段回退模板。第二个LLM说“无幻觉”不是确定性保证。调试视图复用已有trace，缺失或丢弃的非关键trace显式标注；关键业务/操作审计不能随日志轮转一起丢失。CLI/API已满足检验时无需额外三套前端。

## 只读核心机制

复用原13段、600的IntentDecision、500的EventClusterResult与M14固定SOP；不重做归属/分类/执行。1100用事实模板生成回复，可选模型仅选择固定opening/closing语气标识，schema禁止额外字段，正文由代码拼接；不让模型修改或自行复述关键事实。失败回退模板，外部取消仍取消。计划回复明确尚未申请、批准或执行。

MySQL终态提交后生成一条脱敏debug_snapshot。三个视图分别投影输入/实体/候选、窗口/归属/问题、SOP/节点/工具/回复/预算；它们使用同一run/原执行trace和版本。治理节点逐个记录实际起止、下一节点、错误和dispatch IDs；旧ReAct只展示原有阶段/工具，未执行或缺失信息不造记录。输入包含接收时question.version，输出保留终态version；outbox已排队与投影已完成分别表达。

与converse相同身份源，tenant/user/session共同隔离；跨域与过期/丢弃均返回相同404。订单/券/消息等稳定替代ID保留关联，span偏移仍指脱敏前原文。非关键trace独立容量/期限/队列上限，丢弃明确可见；账本不参与轮转。JSON导出防公式字符串，不存隐藏推理、访问令牌或原始工具指令。单机trace key随路径保留，多个写进程用不同路径。

| 定位样本 | 可核对证据 |
|---|---|
| 错意图 | 原/清洗输入、规则/候选、最终code/reason及输入版本；600是唯一主分类 |
| 错归属尝试 | MySQL窗口、候选excluded_reason、两侧引用/整簇守卫、当前question及更正来源 |
| 正式SDK工具超时 | 1000与具体lookup节点失败、实际参数/hash/child timeout、dispatch ID及无成功事实 |
| 恶意润色 | 新增数字/编号/动作/证据或自由正文被schema拒绝，mode=fallback且关键模板完全保留 |
| 日志丢失/过期 | incomplete/dropped_events或404；同消息仍从业务账本零调用回放 |
