# M42｜扩展客诉目录与可执行业务闭环

**状态：** `IN_PROGRESS`；F1活动资格候选已验，F2/F3待续；实际范围见[交接](../../handoffs/M42.md)。2026-10-05规格。
**来源：** PDF文件页25–30的多层意图/更多客诉场景、67–69的业务工具与SOP；新增目录及具体工具/数据模型是本项目设计。
**基线：** M39；复用[M02目录](M02_CONTRACTS_DATA.md)、[M12级联](M12_CASCADE_PIPELINE.md)、[M14 SOP治理](M14_SOP_GOVERNANCE.md)、[M15审批](M15_DURABILITY_APPROVAL.md)、[M20业务/检索MCP](M20_BUSINESS_SOURCE.md)、[M25 PG事实](M25_POSTGRES_FACTS.md)、[M18发布](M18_DATA_FLYWHEEL.md)。可独立实施，不要求先实现M40/M41。

## 明确新增范围

当前只有`DISCOUNT_MISSING / COUPON_UNUSABLE / ORDER_ACTIVITY_QUERY`三个可执行叶子；父节点不能执行。层级结构支持更深目录不代表已经覆盖PDF的广泛业务。本M选择三条有真实合成业务数据与工具消费者的新能力，面向当前个人客户视角，不一次扩展客户/运营/商家全角色后台。

| 新业务叶子（中文目标，code在实施时固定） | 必须与现有意图区分 | 初始闭环 |
|---|---|---|
| 活动参与资格/名额查询 | 不等于查询某订单已经参加的活动 | 明确活动/主体→查询已维护规则、资格与名额事实→说明结果/未知 |
| 订单创建失败客诉 | 不等于已成单的优惠缺失或订单活动查询 | 取得失败尝试标识/来源→查询持久失败记录→解释可证原因与后续动作 |
| 退款后券未退回客诉 | 不等于使用券失败，也不能从用户陈述推定退款完成 | 查询退款与券回退记录→核对关联/状态→事实回复或明确等待/人工边界 |

本M默认提供查询/解释，不接企业支付/自动退款/自动发券。若后续明确要求新增写动作，另写该动作的M15参数/许可/审批/UNKNOWN验收范围，不能用上述名称暗含写授权。未维护的原因/规则返回未知，不生成伪造事实。

## 三个顺序feature

### 1. 可扩目录与首条新查询

交付版本化目录校验、SOP/工具许可绑定及“活动参与资格/名额查询”的完整新增路径，包含PG合成记录维护、真实MCP查询、规则/语料候选、600最终识别、缺槽澄清与事实回复。父子层级、重复code、未知标签、漏SOP/越权工具及旧三叶子兼容均有反例。

只调整新增路径与共享目录必须改变的硬编码，不重写全部领域模型。新增Python解释目录/许可为何校验；原业务资料、识别/检索和工作流页面同步显示新叶子/槽位/真实查询来源，给可运行正常与未知资格实验。被取代的三叶子专用临时入口在核对旧消费者后清除。

### 2. 两类新增客诉及各自证据链

交付订单创建失败、退款后券未退回两条完整查询/澄清SOP，与原相邻意图区分，覆盖失败尝试不存在、退款未完成、券未属于当前主体、记录冲突和已回退等真实合成状态。新记录来自PG持久维护/查询，不用模型生成业务原因；既有MCP委托/回执语义增量扩展。

需要新增schema时用受控增量迁移，说明原行/旧run读取与恢复兼容边界。每条SOP同步中文契约/状态时序、相关课程反例和同run观测；资料页有维护/版本冲突的真实状态。直接相关失效fixture/分支只有独立断言已保留才删除，不重建全项目样本。

### 3. 新目录版本的识别对照与正式发布

冻结新叶子与原三叶子相邻/未知输入后做针对性识别、检索和工具内容验收，比较混淆/拒识/补槽与正确闭环，检查新标签没有挤压原业务。目录、规则、语料split、索引签名、SOP/工具及代码绑定同一候选，实际发布新完整安装并核对旧安装恢复/旧问题读取。

默认切换只依据本次具体证据；未通过新叶子保持不可执行或候选，不把整个目录声明完整。现有学习页面和教程核对精确发布下的实际六叶子范围、失败/未配置与历史版本；删除本轮无引用临时索引/构建副本，保留原发布/待审批依赖。

## 可观察的验收

| 证明目标 | 最小必要证据 |
|---|---|
| 新增业务 | 三条新增能力各自走真实模型→600→MCP→PG事实→回复，补槽/未知/拒绝结果正确；合成个人业务边界明确 |
| 目录安全 | 非叶子、未知code、错父级/槽位/版本、漏绑定、工具扩权被拒绝；不能只增加枚举而无执行消费者 |
| 内容与兼容 | 冻结相邻输入有逐例证据；原三叶子/旧run仍按原版本读取，待审批/UNKNOWN不被新目录重写 |
| 持久协议 | 新字段/迁移/维护CAS/归属、MCP双端schema与回执实测；重复消息不再次查模型或造成新写效果 |
| 学习与发布 | 资料/识别/检索/SOP同一运行能解释新增路径；浏览0模型；新安装与恢复闭包按精确字节验证 |
