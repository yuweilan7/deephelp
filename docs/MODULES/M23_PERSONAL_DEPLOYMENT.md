## 先检查再选拓扑

先读LOCAL_SETUP与.local/DEPENDENCIES，只读核对现有腾讯云资源、CPU/RAM/盘与真实占用/峰值、网络/端口/TLS入口、MySQL/Redis/Milvus/etcd、存量服务、配置与保留资产；旧compose限额不是本次容量证据。若前端/业务源未完成，停止部署并列缺口，不在本次顺便补多个特性。

选定候选为浏览器→同源静态前端/受保护入口→一个DeepHelp应用进程→两个独立Streamable HTTP MCP服务（Business、Retrieval，各一个进程）→现有中间件与模型API。应用自己的账本/outbox/审批与checkpoint仍直接连MySQL；Redis投影及etcd保持既有职责。两个MCP服务独立启动/健康检查/重启/连接池，内部网络访问，浏览器经应用鉴权入口，不直接取得服务凭据或模型密钥。拆服务用于学习实际协议/边界，不增加多worker、不拆仓库或复制引擎。

观测为应用/两MCP→OTel Collector→Tempo与Prometheus→Grafana，复用M21已验证版本/配置；Tempo采用单体/本地持久目录，不增加Kafka/对象存储集群。Grafana管理入口受保护，DeepHelp学习页通过同一trace关联。M21平台若已在此服务器验证，本次复用相同事实与配置，不重复建设另一套。

可保留前端本机开发访问服务器API，但远端验收入口宜提供服务器静态页面，使本机只剩浏览器。用户截图显示4核8GB与低负载，仅为一个时点；应用/MCP/观测同时运行、Milvus索引/查询和训练峰值仍须实测。实际容量不够时报告具体组件与组合，不买资源、扩套餐、盲降核心能力或默认追加Langfuse。完成整个低并发组合的短时实际观察并记录窗口，容量结论不由截图或旧compose上限代替。
