## 要交付的能力

在原会话引擎中，让协调角色把已经明确的业务子任务交给权限受限的专业Agent，收回可核验结果，再推进原问题。先围绕现有订单权益/优惠券业务做两个专业角色的实际协作，不先引入大量业务或通用Agent平台。

专业Agent有独立任务上下文、角色指令/决策入口、允许工具及结构化结果；仅把两个普通函数改名为Agent不算完成。协调角色处理分工、结果冲突和缺失信息，领域事实与权限仍由原代码守卫决定。开发过程仍按AGENTS一主写者顺序交付，与产品运行时的多个Agent分开。

## 委托与结果约束

委托至少固定任务ID、父run/question、服务端身份/归属、角色及版本、任务目标、已确认槽位/来源、允许工具、有效配置快照和预算引用。模型可建议分工；代码只允许已登记角色和任务模板，不能从正文接收任意角色、地址、工具或执行代码。

回执区分完成、需要补充、拒绝、失败、取消与效果未知，保存实际调用ID、合法事实/证据、使用版本及已知usage。模型生成的结论和工具计划不是事实；协调者回查证据/归属/版本，缺证据不输出已解决，冲突不靠另一个Agent投票确认。

只有原600阶段决定主意图，专业角色不能重复主分类或擅自切换原问题。子任务结果不能自动合并其他question、批准旧操作、复活终态问题。工具许可只能收窄，不能由委托扩权；写业务仍经M15的明确审批/唯一领取/查询对账。

## 三个顺序feature

### 1. 首条受控委托与回收路径

交付一个协调角色与订单权益专业Agent：从原已确认意图/槽位进入，执行原只读查询，回收同一run内有证据的结构化结果并形成原事实回复。任务/角色/版本由代码校验，未知角色、越权工具、伪造父任务/证据及过期question版本拒绝。

本feature同步补新增Python文件的中文契约/委托时序，在原工具与工作流页面展示真实分工、输入来源和回执；给一个离线核心实验及预期输出，说明普通SOP与Agent任务的差别。直接替代的临时编排/演示副本同步清除，不留下第二套引擎。

### 2. 两专业角色的有界协作与中断处理

加入优惠券专业Agent，交付至少一个需要订单信息与券状态共同解释的真实协作路径。先用明确顺序委托保证语义；独立只读任务确有收益时才并发，并明确谁等待、谁取消、谁合并结果。配置限制委托深度、任务数、每任务尝试与总deadline；循环委托、重复工具查询及预算耗尽有确定结果。

复用原账本/已有checkpoint与操作记录保存必要任务状态；恢复先核对已完成回执和未知效果，不重新调用已完成子任务。普通新消息不恢复审批或任意RUNNING，现有恢复机制不足时只保留明确可续跑边界。同步讲解取消传播、部分完成/未知、共享预算，并在同run观测中展示；删除本feature造成的失效调度分支及过程副本。

### 3. 业务内容、版本绑定与正式交付

使用已确认的固定正常/反例证明两个专业角色在原业务主链里实际协作，回执来自真实模型与MCP内容，工具事实可以回查。比较单Agent原路径与协作路径的内容、调用和耗时，记录收益/退化；协作先显式选择，不因“多个Agent接通”自动设为默认。

把角色指令、委托策略、工具许可与所需资产纳入原不可变发布/运行绑定，交付精确新安装及旧安装恢复入口。已有学习页逐feature持续更新，本项核对实际协作和正式安装中的说明/源码入口对应关系；清除本轮未引用构建/传输副本，保留发布/审批恢复闭包。

## 可观察的验收

| 证明目标 | 最小必要证据 |
|---|---|
| 实际协作 | 同run可追到协调者、两个专业角色的任务与真实工具证据；固定路径不是伪造Agent transcript |
| 不变量 | 主分类仍只在600；外身份、任务串线、版本漂移、工具越权、无来源事实被拒绝 |
| 有界执行 | 固定动作验证委托环、重复领取、取消/超时/预算不足、一个子任务失败；共享用量不重复结算，未知预留不释放 |
| 中断/重放 | 已完成任务不再请求；UNKNOWN只查对账；审批未同意无写效果；诊断服务故障不重放业务 |
| 内容与教学 | 本次代表协作内容实测；原页面浏览0模型，正常/补槽/失败/未知可解释；新安装与源码/资产精确绑定 |

每个feature均遵守[AGENTS的编码与交付习惯](../../AGENTS.md#每个feature的编码与交付习惯)。离线故障与真实内容各证其范围，真实调用前列影响、样本、调用/token与共享余量，不机械扩成全部历史场景。
