# M17｜500+ 评测集、消融实验与发布门禁

**阶段：** E 评测与发布

**前置：** M13, M16

**来源：** 原 PDF 文件页 41–54、70–74。以下未由原文给出的实现细节均为本复刻方案的工程要求。

## 本模块目标
把M02的小型基线升级为可复跑、可比较、能阻止错误上线的评测体系。不是拿模型自己回答“我做对了吗”，也不是为了复现95%而挑选容易数据。

## 数据组成与隔离
扩展到至少500条测试样本，覆盖15+意图/情境、口语/错字/编号/否定/缺槽位/多轮/多问题交错/未知意图/工具故障/审批重放。500条是规模目标不是统计可信度保证；注明独立case数、变体组数、合成比例和人工核验覆盖率。真实内部业务数据不可使用。

train/dev/test按原始case/近义改写组/模板分组隔离；冻结test和期望值，调参只看dev。模型生成样本可用，但正确标签与工具预期需人工或确定性业务规则核验，记录核验状态。未核验集只能称候选测试集。M18数据回流不得把test转成训练样本。

## 指标口径
意图accuracy、macro-F1/各类precision-recall、候选Recall@K、实体精确率、事件错合并/错拆分、需要澄清比例、正确接管覆盖率与错误接管率、脚本场景完成率、工具调用/参数正确率、危险副作用误执行率、重放幂等、P50/P95延迟、token和实际费用、峰值资源。分类得分不能替代端到端成功。

样本量小的类别给计数和不确定性，不把一个百分比说成真实总体表现。空分母/未执行live必须单独标记，不填0或100掩盖。

## 对照/消融
同一冻结版本比较 Rule+Dense、Hybrid、加Memory/EventCluster、加FastText等增量；至少区分检索提升、额外LLM调用带来的提升、语料泄漏造成的假提升。固定模型配置/采样参数，必要时在受控子集重复测试观察随机性。预算不足时先离线全量+明确抽样live，不假称500条都走了真实模型。

## 发布门禁
原文90%/95%是其自述或目标，不是我们的事实。建议由项目确认开发目标：正常集表现不低于已验收基线，危险写操作无未授权成功、跨用户泄漏为0、关键故障用例全部通过、资源门禁通过。任何硬安全用例失败都阻止发布，不能靠高平均accuracy抵消。

交付固定数据/manifest、跑分脚本、版本化报告、混淆矩阵数据、差异样本、发布判定与模型调用费用记录。CI默认离线；live明确启用。报告要能追溯commit、Prompt/SOP/模型/向量collection/词典版本，不用漂亮图代替可复现实验。

## 接口与分期边界

保留500+目标，但分别报告独立case/变体组/样本数与实际核验覆盖；没有足量可核验数据时诚实未达标，不复制改写凑数。已用于排错的smoke/regression集与未见发布heldout分开，任何依据test结果调参都记录污染并另留未见组。验收按所测子集和配置报告，不能把0个已发现越权外推成绝对无风险。
