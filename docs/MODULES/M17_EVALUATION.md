# M17｜可复跑评测与完整覆盖扩展

**定位：** 核心机制是统一评测和增量对照；500+样本是完整规模目标。
**前置：** M13、M16；只读核心评测不依赖 M15。审批/副作用测试启用时另依赖 M15。
**来源：** PDF 文件页41–54、70–74。实施与真实失败停止规则见 `docs/ROADMAP.md`。

## 做成什么

用同一组合法、独立的输入比较 Rule+Dense、Hybrid、Memory/EventCluster、FastText 的实际结果；能看到错在哪里、额外调用多少，而不只展示成功截图。

先交付当前可核验数据的跑分脚本、版本信息、错例和对照结果。再作为单独特性扩展到15+情境和500+样本；规模未达标时明确写未完成，不用重复改写凑数，也不阻塞已有机制的验证。

## 数据与指标

数据保留 case_id、variant_group、合成标记、split、核验依据。train/reference、dev、test 按来源/会话/模板组隔离；冻结未见测试集，调参只看 dev。模型可以生成候选，标签和预期工具行为必须经人工或确定性业务规则核验；未核验不能算金标。

报告实际样本数、独立case数、变体组数、合成比例、核验覆盖率。已用于排错的 regression 集不能再称未见集；如果依据 test 调参，记录污染并另留未见组。

至少报告意图 accuracy/macro-F1/分类计数、Recall@K、实体保真、事件错合并/错拆分、澄清/接管、工具调用/参数、脚本完成率、P50/P95、真实调用/token/费用。空分母或未运行保持“不适用/未运行”，不能填0或100。选做 M15 时增加越权写入、审批重放和业务效果次数。

## 对照与验收

同一数据、模型配置、候选/调用预算、Prompt/SOP/词典和代码版本比较增量。区分检索变化、额外 LLM 调用与样本泄漏，不预设新增能力必然提升。固定 fixture 应可重跑；真实随机模型不承诺逐字一致。

离线全量与真实抽样分别报告。真实调用的恢复与停止条件遵循AGENTS；不能因免费额度用完就认定全部模型不可用，也不能把离线完成改称真实验收完成。样本未跑全时如实报告覆盖范围。

当前数据集不退于已确认基线，跨归属泄漏、缺槽位调用业务工具、无证据报成功等硬用例必须通过；平均准确率不能抵消硬失败。原作者90%/95%是原文陈述，本项目指标只适用于实际数据和配置。

交付固定数据/manifest、跑分与对照命令、混淆矩阵/错例、实际结果及发布判定。依赖某可选能力的列明确不适用，不制造假数据。完整500+覆盖通过后才记录规模验收完成。

## 首个特性接口与验收入口

`evaluation_cli audit/run`复用原13段Conversation及唯一DTO，四组在评测装配中选择能力，不改变默认业务启动。Dense使用同一Hybrid集合的单Dense路线，K一致；Hybrid延续M12独立dev门限，Memory/EventCluster加入自动归属，FastText只包装原FallbackPort。固定配置/代码/数据/模型内容指纹约束复验，能力差异和不同分数门禁写入报告。

数据核验与运行入口见[应用README](../../modules/deephelp-app/README.md#m17-冻结评测与增量对照)。发布判定必须满足请求覆盖、硬用例、相同单消息对照不退、FastText相对Memory/EventCluster不退、无错合并、持久回读及零调用重放。baseline报告必须同一成功实验；参数/代码变化需要新实验，不能偷偷沿旧结果宣布不退。

离线固定语义/SOP适配器用于全量编排与指标回归，FastText运行状态明确不适用；真实抽样用实际千问/MySQL/Milvus和正式SDK stdio，分别保存内容与费用估算。消息完成不替代整会话关系验证。此特性不训练/重标注M13、不发布索引、不开展M18回流；扩量验收另开特性。
