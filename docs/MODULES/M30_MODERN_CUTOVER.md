# M30｜新路线部署、数据切换与旧服务退役

**状态：** PLANNED；依赖 M25–M28实际交付；M29可选，已实现的部分必须一同备份/验收。

**前置：** M23原部署/恢复、M25全事实迁移、M26历史审批恢复、M27平台容量/恢复、M28页面/跨进程；见 [计划](../../planning/M30/PLAN.md)。

## 新部署与指标去向

在main的特性分支扩展现有infra/deployment与client入口，提供显式安装/启动/停止/健康/备份/恢复/切换路径；bak/mysql-otel完整保留旧脚本，新路线正式入口不永久维护两套驱动与后端选择。保留Python3.14.7、三包/根锁、同引擎、Business/Retrieval独立MCP、Milvus/etcd与应用缓存；Langfuse对象存储为M27已验的SeaweedFS单机容器及持久目录，不购买托管存储。

LLM/业务trace直接进入Langfuse。基础资源、请求/错误/队列/用量分母仍需指标：保留Prometheus/Grafana，应用/两MCP用明确Prometheus暴露入口与中间件原生指标，替代原Collector的指标转发。逐指标核对名称/标签/直方图/零分母与同一attempt用量来源；不同时把OTel与直接指标相加。Langfuse不替代主机/OOM/数据库资源监控，不能为“全家桶”卸载这部分。

先完成指标替代和M28查询功能，再停独立Collector/Tempo。Langfuse SDK需要的OTel包和跨MCPtraceparent保留；只移除确认无消费者的直接exporter/旧装配/Tempo查询依赖。清理CLI、服务入口、包资源、测试、配置、文档与发布指纹引用；源码旧实现可从bak/mysql-otel完整检出，新路线不保留失效重复正式实现。

## 切换协议

迁移先演练一次只读源快照→隔离目标→代表回读/恢复。实际切换在明确维护窗口停旧入口及所有写入者：应用、Business MCP、合成权益、outbox/审核/发布任务、维护API和后台控制任务。不能只停web后假定库不再变化。核对在途/UNKNOWN及调用状态，不宣称已停止便代表无副作用。

取最后一致快照/水位，导入业务与M26状态，核对全表/关系/签名/资产闭包与最终增量，再仅启动新路线一个活动写入口。不可并行双写两库，同一数据库目录不可双实例挂载。Redis/Milvus按原signature/归属/version可验证复用或重建，不混向量空间。

运行bytes变化需新的适用完整发布与精确内容门禁；旧PASS/清单保留原样作为历史，不给新包贴通过标签。先算明确冻结范围、模型调用/token和共享上限；若达到AGENTS的大批量付费边界，先提供具体方案再获授权，不能通过缩减必要发布门禁或改旧hash绕过。

两个回退阶段须区分：新库尚未接受写入，可恢复旧快照/路由；新库已有新消息/审批/业务/发布写入，不能切回陈旧MySQL。优先回滚兼容PostgreSQL的新应用版本；若确需退回旧路线，先停写并按已演练的数据反向迁移/对账办法证明不丢新状态，否则停止并报告恢复事项。Git检出bak/mysql-otel只是代码恢复，不是数据库回退。

## 退役与保留

M25/26/27/28、指标替代、新完整发布、浏览器业务路径和新环境隔离备份恢复均通过后，停用旧MySQL/Collector/Tempo容器与自动启动入口。核对实际进程、服务、端口与消费者确已退出；新路线正常运行不依赖这些服务。

退役不等于删掉恢复数据：保存源快照、数据库/Tempo/Grafana必要持久资料、digest/原配置、两路线安装材料及受引用资产于受保护位置，记录还原方法。数据卷删除不是本模块默认动作；只有确认另有可读恢复副本、无唯一引用且用户明确要求时再清理。临时测试库/集合/脚本只按本次精确创建范围清理。保留bak/mysql-otel、凭据和来源原件。

## 实际验收与停止

本机业务服务关闭后，浏览器连新云环境实际完成新订单/关系维护、客诉补槽/更正、历史回读、同run Langfuse关联；重复receipt零调用、越权/schema拒绝及M26审批一效果恢复通过。逐个重启新应用/两MCP/关键平台组件、断观测服务后业务不重做，恢复后据实标可用或缺失；不承诺SDK短队列自动保证零丢span。

新PostgreSQL库/发布资产与Langfuse元数据、ClickHouse、对象存储、必要队列状态的备份实际恢复到隔离目标；关系/历史/审批/观测可读。做兼容新schema的应用安装回滚，不用两个相同wheel冒充历史代码升级。当前全组合峰值/磁盘增长/恢复时间记录范围；没有长时间证据不宣称长期SLA。

核对根锁三包安装、静态检查与适用回归，所有验收在特性分支；合入main后仅保存/同步，另外核对bak/mysql-otel未变。更新STATE为实际通过的部分，交付访问/恢复方法及未验限制；“完成M30”在部署/隔离恢复特性验收交付后继续切换与旧服务退役，全部特性交付后停止，不自动开公网或买资源。
