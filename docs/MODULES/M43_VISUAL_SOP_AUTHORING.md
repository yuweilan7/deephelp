## 要交付的能力与边界

让用户在原工具与工作流页面编辑SOP节点/条件，看到后端校验和预演结果，再把明确审核的候选纳入发布。当前页面只能读取工作流/做固定审批练习，不是编辑器；静态流程图也不算作者工具。

编辑器输出原GovernedSOP契约，由原执行器消费；前端不实现业务判断或第二套流程引擎。草稿、预演、审核、正式发布与实际业务执行分开；浏览/编辑/结构检查不调用模型。手动操作草稿不表示批准业务写入。

## 三个顺序feature

### 1. 可视草稿编辑与服务端校验

交付读取现有SOP→创建草稿→增删/连接节点→修改受限条件/工具参数映射→保存/重载的完整路径。先支持现有可执行节点，控件生成合法契约；服务端定位悬空边、重复ID、不可达/无终点、环、未知字段/工具、槽位缺失和越权。原版保持不可变。

每次保存返回真实revision/校验状态，刷新/并发旧revision不能覆盖新稿。新增Python讲清草稿/快照/CAS及校验原因；页面提示业务含义、数据来源和具体错误，课程用一个现有SOP修改示例解释图/契约对应。确实替代的只读图胶水和草稿副本当项清除。

### 2. 同执行语义的受控预演

交付显式预演按钮、输入/假设说明、节点时间线、分支条件、缺槽/拒绝/失败结果。默认离线固定动作，不调用模型/真实写工具；预演适配仅提供受控合成工具结果，仍走原拓扑/许可/事实核验。固定预演通过不等于模型或业务通过。

需要真实模型/只读MCP预演时用户明确选择，展示当前候选与预算，使用原鉴权/共享预算和故障边界；候选预演不能产生审批、领取或正式写效果。取消后按实际状态显示，不能因浏览器等待结束宣称服务已停。

同步讲解执行资源拥有者、预演模式和实际/未执行节点，在原run诊断里明确候选hash、来源与模式；保留必要失败结果，删除本次未引用预演中间文件，不复制执行器。

### 3. 审核、版本发布与恢复

交付结构化差异与审核记录，检查基准版本/CAS/完整依赖；审核生成不可变SOP候选，经原完整发布门禁绑定实际运行/工具/资产及真实内容，才切换active。草稿保存或预演PASS不自动生效。

旧问题/待审批/UNKNOWN保持原SOP及参数绑定；升级只作用于新允许的运行，旧图恢复按对应安装/资产闭包。至少一个修改分支在真实业务内容中可观察，旧版恢复也实测。同步版本说明、教程/源码入口和同run图，清除未引用构建/草稿副本，不能删除仍被运行/审批引用的历史版本。

## 可观察的验收

| 证明目标 | 最小必要证据 |
|---|---|
| 作者闭环 | 在实际浏览器编辑、保存/重载、校验定位、预演、审核/发布；后端契约与前端图一致 |
| 编辑安全 | 外owner/同源CSRF/旧revision、非法拓扑、任意表达式/地址/工具许可被拒绝；前端绕过仍被后端拦截 |
| 预演真实语义 | 正常、缺槽、非法事实、失败/取消；离线固定动作0模型/0写效果，真实预演单独记录实际内容 |
| 正式绑定 | 新图实际分支走原引擎；旧问题/审批不漂移；精确发布、切换、安装与恢复验证 |
| 学习与收尾 | 页面展示节点/条件的普通话含义、来源与失败状态；浏览0模型；相关旧入口/临时产物按消费者收尾 |

每个feature执行[AGENTS共性习惯](../../AGENTS.md#每个feature的编码与交付习惯)，编辑器的学习说明与观测不是单独最后补做的工程。验收覆盖变化的SOP及相邻分支，不以全量live弥补结构检查。
