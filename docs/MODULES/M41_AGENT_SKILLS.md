## 要交付的能力

让一个重复使用的业务能力以清楚的输入、步骤、许可工具、输出和版本存在，并由Agent/SOP明确选择执行。首批复用现有“查询订单权益”和“检查券状态”，再组合成受控诊断流程；不另外重写业务查询或分类器。

这里的Skill是本项目后端的可执行能力单元，不是Codex开发技能安装，也不是给Prompt换文件夹名称。Skill说明可以解释步骤；机器契约与代码守卫决定能执行什么，不解析任意Markdown/模型正文为Python、shell或工具授权。

已实现Skill描述包括稳定ID/版本/hash、目标与适用条件、输入/输出schema、所需槽位、允许工具/子Skill、失败/缺槽行为、有限步数及引用版本。结果引用真实工具证据并区分成功、补充、拒绝、失败、取消、未知。唯一SkillReceipt/版本/审批与发布契约见CONTRACTS；组合当前只允许深度2直接只读叶子，不开放递归组合、写Skill或任意委托插件。

Skill选择只接受已登记、版本兼容、当前意图允许的候选；模型推荐不扩大权限。Skill输入不能覆盖已确认实体，输出不能绕过原事实/归属守卫。审批的版本/参数绑定到实际计划及Skill依赖，指令变化不能偷偷改变待审批动作。

## 三个顺序feature

### 1. 版本化Skill与第一条实际执行

交付Skill注册/加载/校验及订单权益查询Skill，从原SOP/Agent入口实际调用现有工具并返回可回查结果。证明缺槽不调用工具、未知Skill/版本/hash/额外参数被拒绝，同版本内容不可原位替换。仅注册描述和在页面列一个卡片不算执行完成。

同步写清新增Python模块、输入输出与Skill/SOP/工具的调用层次；原工作流页面展示实际Skill版本、输入来源、步骤与工具结果。现有课程增加可运行的单Skill实验/预期输出；确实替代的重复查询胶水当项移除。

### 2. 组合Skill与权限/资源边界

交付券状态Skill及有实际业务消费者的组合：先查询订单资料，再带已确认槽位检查券，收回有证据的诊断结果。校验引用闭包、输入映射、环/递归、深度/步数与有限重试；组合只收窄许可，子Skill不能独立获得审批或重置预算。

已有写操作只有在原M15边界下才能成为Skill步骤；取消、部分完成与UNKNOWN按原调用记录处理，不把组合重跑作为恢复。M40已交付时可接入一个受控委托Skill，否则此能力明确不启用，不把缺M40变成整M的虚假前置。

当项补组合数据流与await/资源拥有者说明，在同run显示嵌套步骤、版本及停止原因；给循环/越权/取消反例，清除替代的组合副本和临时产物。

### 3. Skill管理、受控选择与发布

在现有工具与工作流入口提供Skill详情、版本差异、适用意图和明确试运行操作；修改形成新候选，审核后纳入原完整发布，历史run与审批继续绑定原版本。选择策略可先确定性匹配，使用模型选择时必须验证实际选择内容并记录候选与守卫结果。

交付实际代表组合内容、精确新安装、旧版本恢复及历史读取；选择失败/未配置按实际显示，不静默加载远程Skill或回退不受控Prompt。同步现有教程/源码入口并删除无消费者的管理/构建副本，不建设独立市场、外部Skill自动安装或任意代码插件机制。

## 可观察的验收

| 证明目标 | 最小必要证据 |
|---|---|
| 能力可执行 | 单Skill和组合Skill走原MCP事实链；调用/证据/返回值一致，不是固定展示脚本 |
| 结构与权限 | 缺槽、schema错误、未知/漂移版本、引用环、越权工具、子Skill扩权与无证据输出被拒绝 |
| 资源/恢复 | 总预算不因嵌套扩大；取消后资源释放；完成步骤不重复执行，UNKNOWN先查，审批绑定原计划 |
| 版本/内容 | 候选→审核→不可变发布→精确安装/恢复实际可用；变更选择/指令的本次代表内容经真实验证 |
| 学习/观测 | 浏览详情/历史0模型，显式试运行才执行；原run能追到选中Skill、嵌套关系、工具和实际失败原因 |

每个feature适用[AGENTS共性习惯](../../AGENTS.md#每个feature的编码与交付习惯)，不把中文讲解、Skill观测与相关清理推迟到第3项。能力协议证据与模型选择质量分别记录；没有经过真实模型选择时不宣称智能选择已经通过。
