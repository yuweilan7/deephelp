# M22｜面向后端机制的浏览器学习工作台

**阶段：** 在frontend建设一套个人学习界面，逐个可演示特性交付。

**前置：** M20业务/检索MCP与维护API、M21标准观测及平台集成；复用M10/M12会话、M15审批图/MySQLSaver、M16调试、M17评测、M18审核/发布。每个页面只读取直接消费的handoff，不要求为一个页面重读所有模块。

**来源：** 用户2026-10-04要求，个人学习扩展。不是面向公众的客服产品，也不按M编号机械创建一个空tab。

## 页面与教程

页面围绕机制组织；每页有简短原理、前置状态、一个可操作例子、预期观察、实际结果、代码入口和常见反例。默认浏览教程/历史/离线练习不请求模型；真实执行前清楚显示调用模式、预期范围和共享预算，点击才执行。不得重复生产逻辑或用预录成功动画充当本次trace。

## 顺序特性

1. **主对话与业务维护：** 登录/退出、当前身份、对话、补槽、持久历史、事实证据、主链时间线与维护页；这是第一套可日常使用的页面。
2. **MCP与工作流学习：** 协议/schema双端校验、SOP/审批、实际LangGraph与checkpoint页；提供固定动作实验，业务服务真实查询、合成权益练习独立标demo。每一步显示所在进程/接口、实际校验/状态、代码入口及对应span，不能从浏览器任意调用MCP工具或修改checkpoint。
3. **意图检索与记忆实验：** 意图实体、Dense/BM25/Hybrid、多轮记忆和运行观测；同输入对比明确实际模式/版本/分数/耗时，给教程与代码映射、Grafana独立受保护深链接。无需每个tab都真实调用模型才能验收说明/视图，真实执行由用户明确启动。
4. **评测与飞轮页：** 先浏览已有冻结结果/差例/审核/资产版本，再接可取消、可恢复的显式任务。任务状态与已完成证据分开；同一进程先限制一个重任务，不一开始引入多个worker。构建候选不能暗中修改active，发布仍走M18门禁。

每次只选上述一个特性建分支，接口与前端一起完成相应闭环；不生成空handoff或空tab。PLAN在实施时按实际接口差量维护。Grafana负责指标/trace专业探索，前端负责学习步骤、业务事实和受授权投影，不平行重建一套仪表盘后端或将Grafana管理权限暴露给普通测试身份。

## 验收与权限

登录采用个人最小认证并复用可信身份映射，持久历史来自MySQL，补齐当前缺少的会话/消息列表接口；debug日志不能代替历史。前后端保持同一session/question/message语义，网络重投沿用message_id，主动新提问另用新message_id。

前端组件/接口契约/统计展示/教程案例主要离线验收；至少完成本特性新UI→真实后端的实际浏览器内容闭环。浏览器查看历史/trace不新增模型调用，真实执行样本按改变行为与必要反例选。核对维护数据变化、补槽、历史重载、跨身份读/改/观测拒绝、重复消息以及trace与本次响应一致；只检查DOM或HTTP200不够。

审批只有后端显式启用相应实际业务执行口时才显示实际批准入口，绑定operation/版本/参数并独立确认；普通聊天不能批准。synthetic_rights只能在独立演示区域表示合成效果，M20只读业务不冒称已退款/发券。

交付可启动的frontend、API增量、教程/代码映射和浏览器证据；完成当前特性后停止，不自动部署或启动下一个页面。
