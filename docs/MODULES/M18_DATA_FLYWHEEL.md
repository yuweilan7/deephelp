# M18｜审核后更新语料、模型和规则

**定位：** 核心是数据反馈机制；复杂自动发布另做加固特性。
**前置：** M17；使用已有 M10 outbox 和 M13 训练接口。
**来源：** PDF 文件页53–54、70–71、74–76；审核与回退边界是工程改造。流程见 `docs/ROADMAP.md`。

## 做成什么

从一次合成客诉运行采集样本，审核确认意图，更新对应语料/训练输入/规则，再跑固定评测，能回退到上一版本。先把这条人工触发的闭环跑通，不建设每日训练平台或主动学习系统。

高分、SOP成功或用户没反对只影响候选优先级，不能自动证明意图标签正确。没有真实运营数据时报告合成机制演示。

## 最小闭环

1. 采集脱敏输入、候选/决策、工具证据、人工修正、版本/trace引用；同一次运行重复采集不倍增。
2. 候选与金标分开。只有人工确认或经审查的确定性证据规则能晋级，记录来源、审核者、争议、更正和撤回。
3. 为获准样本形成三路可追踪变更：向量语料、FastText训练输入、规则配置。各路独立审核，不要求每条样本三路都写。不能热执行模型生成的代码。
4. 用 M17 固定回归与未见发布样本验证，通过后显式切换版本；未通过不替换当前可用资产。真实构建/调用失败停下报告。

dev/test 及近义变体组不能回流训练；更正或删除能定位所有派生物。轻量 outbox 只提供幂等任务投递，不能当跨文件/向量/模型原子事务。

## 发布加固

作为后续独立特性实现不可变 ReleaseManifest，绑定语料/embedding/FastText/词典/规则/SOP/Prompt/代码版本；准备完整工件后，用单一事实源中的版本化 active 指针切换。run 固定完整版本，不中途换半套资产。

保留上一完整版本以便回退；检查实际双版本容量。待审批或待对账 run 引用的唯一工件不能删除，空间不足停止新发布。选做 M15 后再验证其运行中的版本绑定，不能为回滚改写已批准计划。

## 怎样验收

高置信错误不自动变金标、审核拒绝不入库、重复采集不倍增、近义组不跨split、更正能找到派生物、固定评测可重跑、上一完整版本可回退。发布加固特性还要验证中断时 active 指针仍指向完整版本。

交付一个简明 review CLI、候选/金标数据结构、三路构建入口、回归/回退命令和真实结果。每次只做其中一个可验收特性，同一 M18 handoff 记录核心演示与发布加固各自状态。
