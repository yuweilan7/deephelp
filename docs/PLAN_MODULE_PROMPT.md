# 按模块顺序实施的计划

本文件只定义计划格式，任务范围和交付规则见[AGENTS](../AGENTS.md)，当前成果见[STATE](PROJECT_STATE.md)，能力入口见[ROADMAP](ROADMAP.md)。已完成的模块不重建实施计划。

## 读取与判断

核对分支/HEAD/工作区，读取当前规格、直接前置交接及相关实现/测试。接口、来源或真实依赖有变化时再读取对应资料。保留四种判断：`DIRECT`直接做、`DECOMPOSE`多个顺序特性、`PROBE_FIRST`先验证未知能力、`VERIFY_EXISTING`核验后续做；拆分不意味着多Agent并行。

## 唯一计划文件

明确开始规划或实施某个未完成M时维护一份`planning/Mxx/PLAN.md`，已有适用文件原位更新。仅交付未来模块规格不为每个M预建空PLAN。不新增S、日报或空handoff；计划只写当前未知项和下一步，不复制规格、历史交接和规则。

1. **目标与范围**：输入/可演示结果、全部未完特性及顺序。
2. **复用与改动**：现有接口、预计文件、真实前置及迁移影响。逐feature列本次职责/中文讲解、课程与前端学习/原运行观测、直接相关清理的落点；已有覆盖或不适用时说明理由，共性标准只引用[AGENTS](../AGENTS.md#每个feature的编码与交付习惯)。
3. **证明方法**：正常/关键反例、按[影响选择验收](ROADMAP.md#按影响选择验收)确定离线/针对性live/完整评测。live列样本理由、调用/token范围、共享余量上限及复用依据。
4. **恢复与边界**：失败的定位/续跑、必要状态、无法自行恢复的外部输入及授权外动作。范围内可恢复问题按AGENTS自主处理。
5. **交付**：每特性分支、适用验收、必要handoff/STATE更新和剩余项。每项能力与其讲解/观测/收尾一起完成，不另排“最后全项目整理/补注释/补教学”的feature或M；新的独立用户能力才有独立拆分理由。

探针结果改变后续方案时先更新同一PLAN，不预写整套未知实现。每特性交付后继续同一M，全部完成后停止；完成步骤被规格/handoff覆盖后删除PLAN并修正链接，独立设计仍有用途时才保留。

## 完成条件

计划或命令不是通过证据。必须的真实验收未跑/失败就是未完成，离线/协议证据不冒充内容质量；每个feature同时满足AGENTS的适用编码/交付习惯，全部规格特性通过适用验收并完成Git交付才报告整个M完成。保留M39后的已交付基线，按实际影响验证，不重新执行M32–M39专项。纯规划不实施代码、不创建handoff、不自动提交；用户要求交付规划时按AGENTS完成文档验收/Git流程。
